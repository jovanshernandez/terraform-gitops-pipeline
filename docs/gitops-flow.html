terraform-gitops-pipeline: how a change reaches AWS

One Jenkinsfile, one root per environment. Every branch plans; only master applies, and only the saved plan that was reviewed.

Pull requestany branch, no apply credentials
Static checksfmt validate terraform test tflint, checkov (GitHub Actions + Jenkins)
→
Planplan -out=tfplan with the read-only terraform-<env>-plan role
→
Plan posted for reviewcounts + changed resources, deletes first, commented on the PR; full plan archived
→
Code reviewreviewers approve the diff and the plan together, then merge
merge to master triggers the trunk build
Trunkmaster only
Checks + locksame static checks, then hold terraform-<env> lock until apply ends
→
Planfresh saved plan from the merged commit, archived and fingerprinted
→
Approval gateinput by platform-approvers. prod: always. dev: only on delete or replace.
→
Apply saved planapply tfplan with the terraform-<env>-apply role, bound only here
Nightly drift checkmaster, PLAN_ONLY=true
Plan onlyplan -detailed-exitcode for dev and prod, never applies
→
Exit code 2 = driftbuild marked unstable; summary names the resources that differ
→
Fix through a PRaccept live state in code, or merge to put it back; back to the top lane
State and lockingS3 key per environment, encrypted; use_lockfile = true takes the lock with an S3 conditional write. No DynamoDB table.
Environment config is codeenvironments/dev and environments/prod call one module; sizes, CIDRs and the AMI pin are committed.
HostsPrivate subnets, IMDSv2 only, encrypted gp3, Session Manager instead of SSH, ingress limited to RFC 1918 ranges.
